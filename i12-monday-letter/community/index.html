This week’s letter

Assessments during the transition

A September 22 exchange distinguishes an initial certification checklist from an annual assessment. After a participant caught the mismatch, the discussion returned to how providers and assessors can document work during the transition.

The correction is part of the story. Read the later replies before applying an earlier answer to a different assessment.

Cryptography: follow the current reference

A follow-up question about upstream cryptographic modules prompted a distinction between updated validated functionality and newly added algorithms. The response also points readers away from a legacy policy and toward CR26.

A reply about a particular implementation is not a new rule. Start with the current cryptographic-module reference and retain the context of the exchange.

  • Reply by @pete-gov ↗

Certification changes need room in the schedule

A CR26 page exchange connects class upgrades with the certification rules and discusses the risk of planning a Rev5 transition close to its deadline.

Use the linked rules to establish the requirement; use the conversation to understand the planning concern.

  • Reply by @pete-gov ↗

Clearer dates in the rules documentation

The CR26 release clarifies certification and adoption dates and updates ruleset labels. Its release notes separate content changes from build-pipeline work.

Not every release is a new obligation. The change categories help readers decide which source material to revisit.
